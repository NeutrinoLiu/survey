## 1. Thesis — the representation dictates the pipeline

Hydra-0 represents actions as **action flow**: image-plane trajectories of where visible robot/hand points should move. Because observations and actions live in the *same* visual coordinates, one interface spans human hands, handheld grippers, single-arm, bimanual, and humanoid robots, across tasks and video backbones.

The consequence for data curation is direct and unusual: **the quality criterion is "is there visible motion?"** — not "is the proprioception clean?", which is what every joint-space pipeline (Qwen-RobotManip, ABot-M0) must ask. This makes the filters trivially portable across sources that share nothing else.

## 3. Scope restriction (the first and largest filter)

> *"Because interaction with deformable objects is the focus of this paper, we keep mainly deformable-object interaction data (cloth, cable, rope, bag, and paper)."*

Task-level subsetting before any window-level work. As with EgoVerse's "bounded diversity", the cheapest curation is deciding what never enters.

## 4. Normalization to a shared layout

All main sources converted to a **shared per-episode, per-camera layout**:
- Frames resampled to **480p at 16 fps**
- Cut into **non-overlapping 81-frame windows (≈5 s)**
- Each window carries: dense point tracks, a language caption, **precomputed VAE latents**, and source-dependent embodiment/object annotations

Precomputing VAE latents at ingest is a practical detail worth copying — it moves a per-epoch cost into a one-time preprocessing cost.

## 5. Annotation — heterogeneous backends, uniform schema

| Signal | Method | Coverage gaps |
|---|---|---|
| **Dense point tracks** | **AllTracker** on a **128×128 query grid per window** | universal |
| **Embodiment masks** | calibrated robot rendering, *or* projected hand geometry, *or* SAM 3 refinement, *or* text prompting — whichever the source supports | — |
| **Object masks** | source-provided refined masks or text-prompted **SAM 3** | **unavailable for DROID and EgoDex** |
| **Captions** | dataset-provided, else generated by a VLM | — |

The design explicitly tolerates **missing annotation modalities per source** rather than dropping sources that lack them — handled at training time by conditioning-mode renormalization (§7).

## 6. Window-level filters — three, with published thresholds

*"source-specific combinations of three window-level filters, with thresholds tuned from motion-score histograms"* — note the thresholds are **calibrated empirically from the data's own motion distribution**, not set a priori.

| Filter | Rule | Catches |
|---|---|---|
| **Static-window** | Drop windows whose **90th-percentile visible track path length < 50 pixels at 480p** | Idle segments, pre/post-episode dwell |
| **Frozen-gripper** | Drop windows whose **embodiment tracks fall below the same 50-pixel floor** | Scene moves but the robot doesn't — no action signal |
| **Contentless-caption** | Drop **DROID episodes whose language annotation describes no actionable content** | Junk/empty language labels |

Using a **90th-percentile** statistic rather than a mean is deliberate: it asks "did *anything* move appreciably?" and is robust to the many tracked points that are legitimately static background.

**Targeted coverage repair:** because wrist views are underrepresented, they add a **separate DROID wrist-camera stream of 17-frame windows**, restricted to deformable-object episodes identified from language annotations. Coverage gaps are fixed by adding a targeted stream, not by reweighting.

## 7. Action-flow construction — geometric validity as a filter

For sources **with** geometry (URDF + calibration): robot points are projected into the image plane, and a point is kept only if it is **within image bounds** and **agrees with the rendered depth buffer within a small tolerance**; a **3×3 neighborhood** check *"avoids false rejection at silhouette boundaries."* This is a per-point visibility/occlusion filter — a genuinely fine-grained validity test.

For **video-only** sources (no robot description files, no camera calibration — *"many large interaction datasets"*): dense image-plane trajectories and visibility are recovered directly, no calibration required. This is the mechanism that lets human video and robot data enter the same corpus without retargeting.

Robustness note: *"Moderate calibration error perturbs the two-dimensional motion condition without altering the target video, whereas large projection errors can degrade spatial correspondence."* — the representation degrades gracefully under the most common annotation defect.

## 8. Mixture / sampling policy

Conditioning modes sampled per example with canonical I2V probabilities:

| Mode | Probability |
|---|---|
| None | 0.05 |
| Embodiment | 0.40 |
| Object | 0.40 |
| All | 0.15 |

> *"when a required pool is unavailable, we remove that mode and renormalize the remaining probabilities, while dataset- and camera-specific overrides accommodate unreliable or unavailable annotations and viewpoints."*

This is the cleanest solution in the survey to the ragged-annotation problem: **make annotation availability a sampling-time concern, not an ingestion-time filter.** Sources missing object masks (DROID, EgoDex) simply never get sampled into Object mode.

Track subsampling: **1–128 tracks** in Embodiment/Object mode; **256–1024** from the union in All mode.

## 9. Scaling / results evidence
- **90.4% lower robot-motion error** and **60.2% lower object-motion error** vs. baselines.
- Controlled backbone study: swapping Cosmos 2.5's **native relative 6D end-effector action** for **action flow**, holding flow construction, dataset mixture, and prediction horizon fixed, improves PSNR, SSIM, gripper-flow EPE, FID, FVD on **all five** datasets and object-flow EPE on all four where it is reported. *"This controlled comparison isolates the conditioning representation."*
- **Data-efficiency curves** on six held-out IWS tasks (Bimanual box/rope/sweep, Push-T, Single chain-in-box, Single grasp) using **seeded, nested subsets** of a common eligible cohort — nested subsets again, as in DYNA-2, to prevent distribution shift confounds.
- **Cross-modal transfer**: given only *object* flow extracted from a held-out human demonstration (embodiment flow withheld), Hydra-0 predicts compatible robot motion, and a learned action head maps latent features to executable actions — **without task-specific expert robot demonstrations.**

## 10. What they do not do
- No dedup; no state/action signal cleaning (the representation makes it unnecessary).
- No embodiment retargeting — deliberately replaced by the shared image-plane interface.
- Object masks unobtainable in DROID's cluttered scenes (object EPE omitted from its evaluation), so annotation coverage is uneven and acknowledged.
- Scope is deliberately narrow (deformables); generality of the filter thresholds beyond that regime is untested.

## 11. Transferable takeaways
1. **Publish before/after counts per source.** Hydra-0's table immediately reveals that DROID is 55% static at the window level — a fact of direct use to every project that trains on it.
2. **Tune thresholds from the data's own motion-score histograms** rather than picking constants.
3. **Percentile statistics over means** for motion filters (90th-percentile track path length).
4. **Depth-buffer + neighborhood agreement** as a per-point visibility filter, with the neighborhood specifically to avoid silhouette false-rejections.
5. **Handle ragged annotations by renormalizing sampling probabilities**, not by dropping sources.
6. **Tabulate licenses alongside data volume** — mixing CC-BY-NC-ND into a training corpus is a decision that should be visible.
